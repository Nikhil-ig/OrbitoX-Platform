## 1. Executive Matrix Summary

This matrix establishes the definitive, verifiable relationship between **UI user controls**, **HTTP API endpoints**, **authorization and scoping barriers**, **persistence domain mutations**, **automated test assertions**, and **release status classifications**.

### Classification Taxonomy:
* **Verified**: Source code inspected, real HTTP/API mutation verified, persisted store state confirmed, and test assertions passing in CI/runtime.
* **Partially verified**: Core software flow functioning and tested, but edge error paths, streaming/SSE broadcasts, or multi-node coordination remain polling-based or planned.
* **Implemented, not provider/hardware verified**: Complete software architecture, contracts, and simulated adapters exist, but live physical hardware (e.g. Star/Epson thermal printers) or real merchant payment provider webhooks (e.g. live Stripe/Razorpay) have not been certified with external devices.
* **Planned**: Architected on the technical roadmap; not yet implemented in code.
* **Blocked**: Requires external hardware, provider merchant credentials, or third-party API keys.

## 4. Key Architectural Takeaways

1. **Truthful Boundary Between Internal Software vs External Hardware**:
   All 163 test assertions validate the internal software domain, state machines, REST APIs, responsive frontends, cryptographic tokens, and atomic JSON persistence. No test claims that a physical receipt printer spat out paper or that a live credit card was charged on Visa/Mastercard networks.
2. **Authoritative Pricing Invariant**:
   The client-submitted `priceMinor` is wholly untrusted and disregarded by `POST /api/commerce/orders`. The server looks up the item in the branch's resolved catalog and computes taxes, delivery fees, and order totals authoritatively in minor units.
3. **Idempotency Collision Guard**:
   Order placement endpoints enforce idempotency keys (`window.crypto.randomUUID()`). Retrying an order with the same key and same items returns HTTP 200 with `idempotentReplay: true`. Submitting the same key with different items or different branches is strictly rejected with HTTP 409 `IDEMPOTENCY_CONFLICT`.
4. **Order Tracking Privacy & PII Redaction**:
   Lookups without an unguessable high-entropy `orderToken` (`ordtok_...`) return masked customer phone numbers and redacted delivery addresses, preventing public enumeration of diner PII.
