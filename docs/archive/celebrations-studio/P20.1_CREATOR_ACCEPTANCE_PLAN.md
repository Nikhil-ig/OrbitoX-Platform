## 2. CORE ARCHITECTURAL RECTIFICATIONS (THE 8 CRITICAL POINTS)

### 2.1 Deterministic Section & Node ID Allocation
- **Issue:** Generating `scene_${Date.now()}_${Math.random()}` inside a reducer violates reducer purity, breaking replay, CRDT reconciliation, and deterministic testing.
- **P20.1 Contract:** 
  ```
  Create User Action ──► Controller / Command Layer ──► IdAllocator.allocate() ──► Pure Reducer
  ```
  - Reducers are strictly pure state transformations.
  - Implemented in **[IdAllocator.ts](file:///Users/apple/Documents/Office/company/Orbito/OrbitoX%20Platform/orbitox/apps/celebrations/components/template-studio/engine/IdAllocator.ts)** and wired into **[TemplateEditorController.tsx](file:///Users/apple/Documents/Office/company/Orbito/OrbitoX%20Platform/orbitox/apps/celebrations/components/template-studio/engine/TemplateEditorController.tsx)**.
  - All scene IDs, node IDs, and component instance IDs are fully resolved and unique before entering `TemplateEditorStore`.

### 2.2 Multi-Tenant Cloud Asset Pipeline vs Local Cache
- **Issue:** Local IndexedDB and Blob URLs solve browser memory crashes, but IndexedDB cannot be the authoritative production asset repository in multi-tenant SaaS.
- **P20.1 Architecture:**
  ```
  Client Drop ──► Fast Blob URL ──► IndexedDB Cache (Instant Preview)
                        │
                        ▼ (Background Worker)
                  Upload Service
                        │
                        ▼
             Object Storage (S3 / R2 / GCS)
                        │
                        ▼
             Asset DB Record (tenantId, sha256)
                        │
                        ▼
                   Global CDN
                        │
                        ▼
      Canonical Asset Reference (assetId / https://...)
  ```
  - IndexedDB is strictly positioned as a client-side performance cache and offline buffer.
  - The SceneGraph persists canonical asset references (`assetId` / secure CDN URLs).

### 2.3 Semantic Content Slot Schemas
- **Issue:** Generic key extraction (`headline`, `subhead`, `ctaText`) is too shallow for complex, semantic website templates.
- **P20.1 Contract:** Templates declare formal semantic content schemas and slots:
  - **SaaS Blueprint:**
    - `hero.title`, `hero.subtitle`, `hero.primaryCta`, `hero.secondaryCta`, `hero.previewImage`
    - `metrics[]: { label, value, change }`
    - `features[]: { icon, title, description, link }`
    - `pricingPlans[]: { name, price, billingPeriod, features[], isPopular, ctaText }`
    - `testimonials[]: { quote, authorName, authorRole, avatarUrl, companyLogo }`
  - **Agency Blueprint:**
    - `editorial.leadIn`, `editorial.headline`, `caseStudies[]`, `clientLogos[]`, `contactDetails`
  - **Celebrations / Wedding Blueprint:**
    - `celebrants.partnerA`, `celebrants.partnerB`, `events[]`, `rsvpConfig`, `storyMilestones[]`
  - The migrator performs typed slot mapping with graceful fallbacks rather than ad-hoc string matching.

### 2.4 Responsive Primary-Cascade Inheritance (Figma Sites Model)
- **Cascade Rule:**
  ```
  PRIMARY Desktop (1440px) ──────► Cascades to Tablet (768px) ──────► Cascades to Mobile (375px)
                                           │                                   │
                                    Local Overrides                     Local Overrides
                                  (Cascade to Mobile)                    (Strictly Local)
  ```
- **Broadened Art-Direction Scope:**
  Responsive overrides apply not only to width/height/padding, but to:
  1. `visibility`: Show/hide sections or nodes per device (`hidden: true`).
  2. `order`: Reorder elements within flex/grid layouts on smaller viewports.
  3. `composition`: Switch from multi-column grid to vertical stack.
  4. `layoutMode`: Switch between `flow`, `flex`, `grid`, and `absolute`.
  5. `crop / focalPoint`: Mobile-optimized framing for background media.
  6. `motion`: Disable heavy ambient physics on mobile; trigger simplified entrance fades.
  7. `3D behavior`: Adjust camera FOV, disable particle starfields, or lock orbit controls on mobile.

### 2.5 Single Canonical Project Document Hierarchy
Every level of the system derives from a single, unambiguous document tree:
```
PROJECT (Canonical Root)
   │
   ├── PAGES (Navigation, Slugs, SEO Metadata)
   │     └── SECTIONS (Order, Anchor IDs, Backgrounds)
   │           └── SCENEGRAPH (Nodes, Hierarchies, Auto Layout, Freeform)
   │                 ├── Layout Engine (Flex, Grid, Flow, Absolute)
   │                 └── Behavior Engine (Interactions, Motion, Triggers)
   │
   ├── THEME (Design Tokens)
   │     ├── Color Palette (Primary, Accent, Surface, Text, Gradients)
   │     ├── Typography System (Fonts, Scales, Line Heights, Letter Spacing)
   │     └── Spatial Scales (Spacing, Radii, Shadows, Blur)
   │
   └── LIBRARIES (Reusables & Assets)
         ├── Master Components & Instances
         ├── Media Assets (Images, Videos, Vector SVGs, 3D Models)
         └── Motion & Spatial Presets
```
- **Rule:** There are no competing sources of truth. The Canvas, Inspector, Page Tree, and Runtimes are pure reflections and mutators of this canonical document.

### 2.6 Published Runtime Parity for 3D & Motion
- **Issue:** Studio 3D and Motion worked inside isolated studio tabs, but guest/preview runtimes could render flat static content.
- **P20.1 Contract:**
  - **3D Spatial Runtime:** `SceneGraphRenderer` registers a native WebGL node adapter. When a 3D element exists in the scene graph, the published guest page (`/e/[slug]`) and preview modal mount a Three.js canvas rendering the authentic 3D mesh and lighting.
  - **Motion Runtime:** `SceneGraphRenderer` inspects `node.motion`. In published and preview mode, elements execute native Web Animations API (WAAPI) keyframe animations with hardware acceleration.
