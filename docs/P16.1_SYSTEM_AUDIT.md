## 2. CANVAS ENGINE AUDIT

### 2.1 Rendering Pipeline
The canvas renders scenes in a continuous vertical document flow inside `CanvasWorkspace.tsx`.
1. `StudioShellContent` retrieves `schema.scenes` filtered by the active page's `sectionIds` (`activePageSections`).
2. For each section, a wrapper `div` is mounted with an action toolbar, rendered dimensions, and two stacked layers:
   - **Layer 1 (Bottom)**: `SceneGraphRenderer`, which recursively parses `sceneGraph.renderOrder` and renders DOM nodes via adapters (`BasicNodeAdapters`, `AdvancedNodeAdapters`, `SmartNodeAdapters`).
   - **Layer 2 (Top)**: `CanvasInteractionLayer`, an absolute overlay matching the section bounds. It measures DOM elements via `CanvasCoordinates.measureNode()` and renders selection boxes, 8 resize handles, rotation stem, and bounding box badges.

### 2.2 Critical Failure Identified: Element Click Disconnection
In `CanvasWorkspace.tsx`, `<SceneGraphRenderer>` is instantiated as:
```tsx
<SceneGraphRenderer
  sceneGraph={scene.sceneGraph}
  device={viewport}
  tokens={designTokens}
  isEditorMode={true}
  resolvedState={resolvedState}
  schema={schema}
  // BUG: onNodeClick prop was omitted!
/>
```
Because `onNodeClick` was not forwarded from `CanvasWorkspace` into `SceneGraphRenderer`, unselected nodes rendered by node adapters received pointer events that were swallowed without triggering `onSelectNode()`. Only nodes already selected or selected via the Layers panel were visible to the top interaction layer.

### 2.3 Coordinate System & Double-Scaling Flaws
`CanvasCoordinates.ts` accurately computes:
$$\text{SceneX} = \frac{\text{ClientX} - \text{ArtboardRect.left}}{\text{Zoom}}$$
$$\text{SceneY} = \frac{\text{ClientY} - \text{ArtboardRect.top}}{\text{Zoom}}$$
However, when an element is inside a CSS flex or flow container (e.g. `position: 'flow'`), altering its `x` and `y` via dragging does not translate into CSS coordinates unless the node's position is explicitly promoted to `position: 'absolute'`. Dragging a flow node causes layout jitter or jumps because the DOM flow resists direct coordinate manipulation.

### 2.4 Viewport & Zoom/Pan System
- **Viewport handling**: Supports Desktop (1440px), Tablet (768px), and Mobile (390px). Canvas centers the artboard and sets explicit max-width.
- **Zoom**: Smooth scaling from $0.25\times$ to $2.5\times$ using `wheel` events when `metaKey` or `ctrlKey` is held.
- **Pan**: Controlled by Spacebar + Pointer Drag or Middle-click drag, updating continuous offset $\{x, y\}$.
- **Flaw**: When zooming, the zoom origin defaults to canvas center rather than the pointer location, causing the canvas to drift away from the user's cursor focus.

## 3. SCENEGRAPH ARCHITECTURE AUDIT

### 3.1 Node Structure (`SceneGraphTypes.ts`)
The SceneGraph is structured as a normalized tree stored in a flat dictionary:
```typescript
interface SceneGraph {
  schemaVersion: number;
  rootNodeId: string;
  nodes: Record<string, SceneGraphNode>;
  renderOrder: string[];
}
```
Every node implements `SceneGraphNode`:
```
SceneGraphNode
├── id: string (UUID)
├── kind: SceneNodeKind (40+ types)
├── name: string
├── parentId: string | null
├── children: string[]
├── geometry: NodeGeometry (x, y, width, height, rotation, opacity, zIndex, position)
├── layoutMode: 'flex' | 'grid' | 'stack' | 'freeform' | 'auto'
├── layoutConfig: AutoLayoutConfig | GridLayoutConfig
├── style: NodeStyle (typography, background, border, shadow, effects, padding, margin)
├── responsive: ResponsiveOverrides per viewport (tablet, mobile)
├── motion: NodeMotion (in, hover, scroll)
├── interactions: NodeInteraction[] (onClick, onTap, trigger)
├── binding: NodeBinding (fieldKey, bindingType, fallback)
├── component: NodeComponentConfig (masterComponentId, overrides)
├── locked: boolean
├── hidden: boolean
├── smartProps: Record<string, any>
└── textContent?: string
```

### 3.2 Parent-Child & Tree Traversal
- **Root Node**: Represents the section artboard container (`kind: 'frame'`).
- **Render Order**: Flat array of root node IDs. Child nodes are resolved recursively by iterating `node.children`.
- **Flaws Identified**:
  1. No cycle detection or depth limiter in recursive rendering.
  2. If a node is deleted, its ID was sometimes left behind in `parent.children`, creating ghost references.
  3. No multi-selection group bounding box computation in the SceneGraph engine; multi-selection treats each node independently rather than as a unified bounding group.

## 4. COMMAND & STORE SYSTEM AUDIT

### 4.1 Mutation Pipeline
The store executes mutations through a strict unidirectional lifecycle:
```
User Action (Click, Drag, Keydown, Input)
  ↓
TemplateEditorController Facade
  ↓
TemplateEditorStore.dispatch(command)
  ↓
mutateDraft(draft => { ... })
  ├── 1. Push deep clone of current state to TemplateEditorHistory.past
  ├── 2. Apply Immer-style synchronous mutation to draft
  ├── 3. Enforce invariants (page-scene synchronization, order indices)
  └── 4. Re-resolve snapshot (tokens, responsive values, bindings)
  ↓
TemplateEditorStore.notify() (triggers useSyncExternalStore in UI)
  ↓
TemplateEditorPersistence.scheduleAutosave() (debounced 600ms to LocalStorage)
```

### 4.2 Strengths & Preserved Foundations
- **True Unidirectional Immutability**: All state updates go through `mutateDraft()`. No rogue component state bypasses the store.
- **Undo/Redo History**: Snapshots capture the complete schema draft. Reversing a mutation (`controller.undo()`) restores project truth cleanly.
- **Persistence**: Debounced 600ms autosave writes to `localStorage` under `orbitox_celebrations_template_schema_${slug}`.

### 4.3 Weaknesses Identified
- Large payloads: Saving the full template schema JSON on every mutation causes performance bottlenecks when schemas exceed 500KB.
- Undo granularity: Slider drags (such as opacity or font size) can produce dozens of history frames unless throttled or committed only on `pointerup`.

## 5. TEMPLATE & SECTION SYSTEM AUDIT

### 5.1 Template Switching Architecture
In `StudioShellContent`:
- `handleReplaceSite` receives a `StudioTemplateMeta` blueprint, constructs an instantiated `TemplateSchema`, and dispatches `REPLACE_PROJECT`.
- **Failure**: Replacing a template discards customer content (custom images, event details, RSVP fields, guestbook entries) unless explicitly ported through a data-preserving content mapping migrator.

### 5.2 Section System Architecture
- `WebSectionLibrary.ts` defines 30+ production section blocks.
- `INSERT_SECTION` and `ADD_TEMPLATE_SECTION` insert a new `TemplateSceneDefinition` and update both `draft.scenes[]` and `activePage.sectionIds[]`.
- **Failure**: Sections lack a first-class "Section Variant" concept. Users cannot swap a section's art direction (e.g. from Bento Grid to Split Editorial) without deleting and re-creating the section from scratch.

## 6. INSPECTOR & PROPERTIES PANEL AUDIT

### 6.1 Information Architecture
`PropertiesPanel.tsx` is organized into:
1. **No Node Selected**: Section & Document Inspector (Section Name, Nav Anchor, Page Transitions, AI Remix).
2. **Node Selected**: Object Inspector with 4 Tabs:
   - **Essentials**: Text content, Image source/upload, Button label/link, Dimensions (W/H), Layout direction.
   - **Design**: Typography (Font, Size, Weight, Align), Box Model (Padding X/Y), Corner Radius (Linked/Unlinked), Opacity.
   - **Behavior**: Parallax Depth Plane, Entrance Motion Preset, Hover Micro-animation.
   - **Advanced**: CMS Variable Binding, Semantic HTML Tag, Developer Mode diagnostics.

### 6.2 Audit Findings
- **P19 Result**: All 35 controls were wired to real store dispatches (`SG_UPDATE_NODE_PROPERTY`, `SG_UPDATE_STYLE`, `SG_UPDATE_GEOMETRY`, `UPDATE_SCENE`).
- **Remaining UX Limitations**:
  - Color picker is currently a plain text/preset selector without an interactive 2D color canvas (HSV/HEX/RGBA picker).
  - Box model lacks direct interactive click-to-edit margin controls on top/right/bottom/left edges.
  - No visual cubic-bezier curve editor for transition easing.

## 7. SUMMARY OF ARCHITECTURAL GAPS

| Subsystem | Current State | Architectural Gap |
|---|---|---|
| **Canvas** | Single click select, 8 handles | No marquee multi-select, no snap-to-edge smart guides, no zoom-to-cursor. |
| **SceneGraph** | Flat dictionary with children arrays | Flow nodes fight absolute coordinate transforms; no group bounding calculations. |
| **Templates** | Atomic project replacement | Destructive content loss on template switch; no data retention mapping. |
| **Components** | Basic schema flag | No true master-to-instance inheritance with visual override tracking. |
| **Assets** | In-memory + LocalStorage Data URLs | No image cropping, focal point picker, or automated WebP compression. |
| **Motion** | Static preset dropdown | No keyframe timeline editor or visual bezier curve tuning. |
| **AI Engine** | Modal command executor | No contextual inline canvas generative editing or conversational design assistant. |
